# Синтетические шаблоны аудита H2

Эти файлы показывают формат и не содержат настоящих статей или решений людей.
Значения с доменом `example.invalid`, идентификаторами `demo` и повторяющимися
хешами вымышлены.

## Файлы

- `works.example.jsonl` — закрытая карточка работы со служебными метаданными;
- `artifacts.example.jsonl` — точный очищенный вход и его контрольная сумма;
- `rights.example.jsonl` — отдельные синтетические записи прав по операциям;
- `h2_audit_run.example.json` — версии и контрольные суммы одного запуска;
- `h2_queries.example.jsonl` — воспроизводимый синтетический поисковый запрос;
- `h2_audit_frame.example.jsonl` — строка воспроизводимого отбора и закрытое
  соответствие `annotation_item_id` с `work_id`;
- `h2_annotation_form.example.jsonl` — то, что разрешено показать
  разметчику;
- `h2_adjudication_form.example.jsonl` — отдельный бланк арбитра с явным типом
  конфликта;
- `h2_labels.example.jsonl` — назначение ГРНТИ, два независимых ответа и
  отдельный арбитраж разногласия.
- `h2_audit_report.example.yaml` — полный незаполненный отчёт и решение
  `pass|revise|reject`.

Соответствующие JSON Schema находятся в [`../schemas/`](../schemas/). Общий
порядок работы описан в
[`docs/templates/H2_AUDIT_TEMPLATE.md`](../../docs/templates/H2_AUDIT_TEMPLATE.md).

## Как использовать

1. Не заполняйте примеры настоящими данными.
2. Создайте рабочие копии в корне `manifests/`; эти файлы исключены из Git.
3. Выдавайте экспертам только отдельные копии обезличенного бланка.
4. Используйте псевдонимы разметчиков; связь псевдонима с человеком храните
   вне Git.
5. Ответы добавляйте новыми строками. Не исправляйте независимый ответ после
   обсуждения или арбитража.

Синтетический пример намеренно показывает разногласие C4/C5 и решение арбитра
C4, чтобы продемонстрировать неизменяемую историю решений.

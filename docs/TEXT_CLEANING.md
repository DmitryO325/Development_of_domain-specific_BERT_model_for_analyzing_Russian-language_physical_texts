# Версионированная очистка текста

Рабочая версия: `text-clean-conservative-v3`. Это инженерная подготовка
кандидатов для проверки, а не сборка допущенного обучающего корпуса.

**Замечание от 01.10.2026:** в v1 обнаружена ошибочная мягкая склейка
`ускоВ` на странице с буквицей. Пакет сохранён как есть, качество не принято.
С разрешения пользователя выпущена v2: подозрительная склейка при переходе
строчная → заглавная сохраняется без изменения и с замечанием. Это устраняет
добавленную очисткой ошибку, но не восстанавливает порядок исходной буквицы.
[Проверка и проба OCR на четырёх сложных страницах](../data/qa/jinr_cleaning_review_20261001/REVIEW.md).

## Что реализовано

`src/preprocess/text_cleaning.py` обрабатывает текст отдельных физических
страниц. Он не читает файлы и не обращается к сети:

- приводит окончания строк к LF и Unicode к NFC;
- заменяет неразрывные пробелы обычными, убирает пробелы в конце строк;
- склеивает мягкий перенос U+00AD на границе букв внутри страницы, кроме
  подозрительного перехода строчная → заглавная;
- склеивает обычный дефис на границе строк только для слов из явного списка
  `join_words`, сохраняя регистр;
- заменяет пустой строкой только явно перечисленные колонтитулы из
  `exclude_lines`, проверяя точный исходный текст до нормализации;
- сохраняет неоднозначные дефисы, табуляцию, управляющие и частные символы
  Unicode, отмечая их для последующей проверки.

Межстраничные переносы не склеиваются. Внутренние пробелы и табуляция не
схлопываются: они могут отражать формулу или таблицу. Формулы, таблицы, порядок
чтения и потерянные буквы автоматически не восстанавливаются. Отсутствие
замечаний не означает отсутствие ошибок.

`src/preprocess/cleaning_io.py` проверяет происхождение входов, применяет
явные исключения страниц и строк и готовит неизменяемый пакет. Команда запуска —
`scripts/clean_texts.py`.

## Входной план и проверки

План соответствует
[`text_cleaning_plan.schema.json`](../manifests/schemas/text_cleaning_plan.schema.json).
Для каждой работы задаются `work_id`, ID зарегистрированного исходного TXT,
относительный путь к `pages.jsonl` и его SHA-256, номера исключаемых страниц
с причинами, список разрешённых слов для склейки и список `exclude_lines`.
В v3 используется `schema_version=text-cleaning-plan-v2`; `exclude_lines`
обязателен у каждой работы, но может быть пустым, как и остальные списки.
Нумерация физических страниц начинается с 1, независимо от печатного номера.

У каждого исключения строки задаются `page_number`, `line_number`,
`expected_text` и непустая `reason`. Сопоставление строгое: пробелы в конце,
NBSP и табуляция должны присутствовать в `expected_text` в исходном виде.
Нумерация строк начинается с 1; разделители CRLF, CR и LF считаются одним
переводом строки, другие управляющие символы строки не разделяют.
При несовпадении, дубликате, отсутствующей строке или ссылке на уже исключённую
страницу весь план отклоняется до записи. Нельзя исключениями строк удалить
всё содержимое непустой страницы.

Строка не вырезается вместе с разделителем: вместо неё остаётся пустая
строка. Это сохраняет номера исходных строк в журнале и не позволяет склеить
слова через удалённый колонтитул. Преобразование отмечается кодом
`remove_explicit_line`; причина и точное содержимое сохраняются в плане
и `excluded_lines` отчёта `text-cleaning-report-v2`. Автоматического
распознавания колонтитулов по регистру, цифрам или названию журнала нет.

Перед обработкой проверяются:

- рабочие реестры и их связи;
- наличие исходного полного текста и родительского PDF той же работы;
- точные байты, SHA-256 и размеры зарегистрированных файлов;
- версия и метод извлечения, порядок страниц, хеш и длина каждого TXT;
- побайтовое воспроизведение полного исходного TXT из постраничного экспорта
  по правилам того же извлекателя.

Дубликаты ключей JSON, неизвестные поля, повторные работы, недопустимые пути,
символические ссылки, отсутствующие страницы и пустой остаток отклоняются.
Исключение страницы удаляет её только из производной копии; исходный TXT,
PDF, метаданные и постраничный экспорт сохраняются.

## Как запустить

Локальный план v3 по 35 журнальным статьям ОИЯИ:
[`jinr_articles_cleaning_20261005_v3.json`](../manifests/imports/jinr_articles_cleaning_20261005_v3.json).
План и данные находятся вне Git; на другой машине эти ссылки могут отсутствовать.

Проверка без создания каталога результата:

```bash
.venv/bin/python scripts/clean_texts.py \
  manifests/imports/jinr_articles_cleaning_20261005_v3.json --dry-run
```

Запись проверенного пакета:

```bash
.venv/bin/python scripts/clean_texts.py \
  manifests/imports/jinr_articles_cleaning_20261005_v3.json
```

Результат помещается в
`data/qa/preprocessing/<preprocessing_version>/<SHA-256 точных байтов плана>/`:

- `plan.json` — точная копия входного плана;
- `report.json` — происхождение, хеши кода и схем, исключённые страницы,
  точные исключения строк с причинами, изменения и замечания с номерами
  исходных страниц и строк;
- `documents/<SHA-256 исходного TXT>/text.txt` — общий очищенный текст;
- `documents/<SHA-256 исходного TXT>/pages/page_XXXX.txt` — отдельные страницы
  с сохранёнными исходными номерами.

Общий текст соединяет страницы двумя LF; завершающий LF страницы, если он
был, сохраняется отдельно. Поэтому изменение длины общего текста отражает
не только очистку, но и иной разделитель страниц относительно извлекателя.

Запись сначала выполняется во временном каталоге и только затем публикуется
целиком. Одновременную запись одного пакета блокирует lock-файл. Точный повтор
сверяет состав и байты файлов и не меняет время их записи. При конфликте
команда останавливается, ничего не перезаписывая. Не удаляйте lock-файл
работающего процесса. После аварийного завершения сначала убедитесь, что
процесс действительно остановлен.

Хеши реализации входят в отчёт. Даже косметическая правка соответствующего
кода после публикации может сделать повтор конфликтным. Старый пакет нужно
сохранять; изменения правил требуют новой версии и нового плана.
Текущий обработчик v3 отклоняет планы v1/v2, не применяя к ним новые правила.
Старые пакеты остаются доступными для чтения; для их повторного получения
нужна соответствующая историческая реализация, а не замена версии в плане.

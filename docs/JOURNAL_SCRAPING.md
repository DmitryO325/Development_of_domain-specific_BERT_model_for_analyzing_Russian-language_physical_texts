# Сбор статей физических журналов

`scripts/download_journals.py` собирает публичные русские карточки и PDF
УФН, ЖЭТФ, «Писем в ЖЭТФ» и «Квантовой электроники». Исходники сохраняются локально;
OCR, регистрация в рабочих реестрах и допуск к обучению выполняются отдельно.
Ответ редакции не подменяется успешным скачиванием.

## Источники и команды

Код источника `jetp` обозначает ЖЭТФ, `jetp_letters` — «Письма в ЖЭТФ»,
`quantum` — «Квантовую электронику», `ufn` — «Успехи физических наук».

Проверить только правила автоматического доступа:

```bash
.venv/bin/python -u scripts/download_journals.py probe jetp --allow-network
```

Собрать очередную порцию каждого архива:

```bash
.venv/bin/python -u scripts/download_journals.py crawl jetp --max-requests 60 --allow-network
```

```bash
.venv/bin/python -u scripts/download_journals.py crawl jetp_letters --max-requests 60 --allow-network
```

```bash
.venv/bin/python -u scripts/download_journals.py crawl quantum --metadata-only --max-requests 60 --allow-network
```

```bash
.venv/bin/python -u scripts/download_journals.py crawl ufn --max-requests 20 --timeout 60 --allow-network
```

Это отдельные команды. Разные сайты имеют независимые паузы; запускать несколько
команд для одного источника не требуется. Общая блокировка источника всё равно
сериализует его сетевые запросы.

Для «Квантовой электроники» в примере включён `--metadata-only`: при проверке
13 октября первый явно опубликованный PDF вернул HTTP 403, хотя HTML-страницы
открывались. В теле ответа указано: «Файл доступен по подписке».
Этот режим не запрашивает PDF и не обходит ограничение; сведения
о статьях можно собирать отдельно. Без флага сборщик пытается получить
опубликованный PDF, но при отказе доступа останавливается.

Для УФН отдельно распознаётся явная пометка «Полный текст предоставляется
по подписке» вместе с отключённой кнопкой PDF в блоке полного текста текущей
статьи. Такая карточка сохраняется без PDF, с причиной
`document.extra.pdf_access_status=subscription_required`; обход продолжается.
Ссылка `citation_pdf_url` в этом случае не запрашивается. Это не разрешение
следовать перенаправлению или обходить подписку: неожиданное перенаправление
по-прежнему останавливает сбор. Наличие пометки только в аннотации, скрытом
блоке или другой статье не считается подтверждением подписки.

Старые ссылки УФН поддерживаются без подстановки адресов: например,
`/ufn17/ufn17_12/Russian/r1712a.pdf` и
`/ufn2018/ufn2018_3/Russian/r20183a.pdf`. Год и номер выпуска в каталоге
и имени PDF сверяются с карточкой; ссылка должна быть опубликована в
`citation_pdf_url` или блоке полного текста текущей статьи. Презентации
`*_p.pdf`, обложки, чужие выпуски и конфликтующие ссылки не принимаются.
Повтор обычного обхода перечитывает сохранённые HTML и догружает ранее
нераспознанные PDF; обновлять страницы через `--refresh-url` не требуется.
Ранее закреплённые карточки без PDF проверяются с воспроизведением прежнего
отбора ссылок, без изменения исходников и остальных полей. Новая версия
карточки с PDF регистрируется отдельно, с сохранением идентификатора работы.

`--max-requests` ограничивает обращения к сайту, а не число PDF. Между
завершением запроса и началом следующего проходит не меньше 60 секунд.
Более строгий `Crawl-delay` или `Retry-After` увеличивает паузу.
Порция в 60 запросов занимает примерно час плюс время передачи данных.

Повтор той же команды продолжает работу: обход начинается со страницы архива,
но уже полученные ответы читаются из проверенного кеша. Нулевой лимит запросов
снимает ограничение порции. `--max-articles` учитывает и уже сохранённые
карточки; для последовательного расширения массива оставьте его равным нулю.

Без `--allow-network` разрешено только чтение локальных ответов. Изменение
`--output-dir` или `--state-dir` не сбрасывает сетевую паузу.

### Выбор старого тома ЖЭТФ

Для обхода одного тома используйте номер из опубликованного списка на сайте:

```bash
.venv/bin/python -u scripts/download_journals.py crawl jetp --volume 169 --max-requests 20 --timeout 60 --allow-network
```

Сборщик проверяет русскую форму выбора тома, отправляет её параметры и
сохраняет исходный ответ HTTP 302. Переход разрешён только к точному адресу
выбранного тома из `Location`; затем проверяются `robots.txt` и русский
заголовок страницы. Обратные ссылки на другие тома не обходятся. Недоступный
в списке номер, изменившаяся форма или другое перенаправление останавливают запуск.

`--volume` действует только для `jetp` и несовместим с `--start-url`.
Повтор команды продолжает тот же том: сохранённые форма, переход, карточки
и PDF читаются из кеша. POST входит в общий лимит запросов и использует ту же
минутную паузу. В `last_run.json` поле `selected_volume` и описание `scope`
ограничивают результат одним томом; весь исторический архив команда не обещает.

Для явной перепроверки формы и её POST-ответа добавьте
`--refresh-url https://www.jetp.ras.ru/cgi-bin/r/index` вместе с
`--allow-network`. Прежние свидетельства сохраняются. Повреждённый кеш
не обходится повторной загрузкой, в том числе с этим флагом.

## Непрерывный сбор

`scripts/collect_continuously.py` управляет сохранённой очередью УФН, ЖЭТФ,
«Писем в ЖЭТФ», пяти журналов Иоффе и Quantum. Это получение исходников,
а не регистрация в общих реестрах или допуск к обучению. Quantum остаётся
в режиме **только метаданных**. ОИЯИ и Math-Net в эту очередь не включены:
для них используются отдельные API-клиенты и действуют отдельные ограничения.

Один раз создайте очередь по уже проверенному локальному кешу формы ЖЭТФ:

```bash
.venv/bin/python -B -u scripts/collect_continuously.py init --ioffe-origin http://journals.ioffe.ru
```

Команда не обращается к сети и не перезаписывает существующую очередь.
Тома ЖЭТФ берутся из опубликованной формы, а не из придуманного диапазона.
При отсутствии или повреждении кеша создание останавливается.
Адрес Иоффе выбирается явно; автоматической смены HTTPS на HTTP нет.

Продолжение очереди на macOS с защитой от автоматического сна при бездействии:

```bash
caffeinate -i .venv/bin/python -B -u scripts/collect_continuously.py run --allow-network
```

На других системах запускайте ту же команду без `caffeinate -i`.
Закрытая крышка, принудительный сон, выключение или закрытие терминала всё ещё
могут прервать работу. После этого запускается та же команда `run`:
завершённые задания пропускаются, исходные ответы незавершённых берутся из кеша.
Для обычной остановки используйте Ctrl+C: дочерние сборщики завершаются,
а очередь и журналы сохраняются. Не запускайте параллельно ручные команды
тех же сборщиков. Два непрерывных запуска одного проекта блокируются.

Просмотр состояния в другом терминале, без сети и изменения файлов:

```bash
.venv/bin/python -B scripts/collect_continuously.py status
```

Состояние находится в `manifests/imports/collection_queue/queue.json`.
Каждая попытка имеет уникальный каталог `attempts/<идентификатор>/`
с `output.log` и `summary.json`. Итог сверяется с идентификатором запуска,
источником, томом/журналом, режимом и кодом завершения. Старый `last_run.json`
не используется как доказательство успеха новой попытки. Эти локальные файлы
игнорируются Git; количество заданий обхода не равно количеству статей.

После потери управляющего процесса состояния `running` и `interrupted`
сначала сверяются с сохранённым `summary.json` именно своей попытки.
Код завершения прежнего процесса при этом неизвестен и не подставляется.
Подтверждённое завершение сохраняется; явный временный сетевой сбой получает
возрастающую паузу; корректное прерывание разрешает продолжение из кеша.
Запрет доступа, противоречивый, чужой, повреждённый или отсутствующий итог
оставляет задачу в `blocked` до проверки. Такая сверка выполняется под общей
блокировкой: пока прежний дочерний сборщик ещё работает и удерживает её,
второй управляющий процесс не запускает сбор заново.

Одновременно работают не более пяти сборщиков — по одному на сайт.
Тома ЖЭТФ и журналы Иоффе обходятся последовательно внутри своего сайта.
Общий ограничитель каждого источника сохраняет паузу не меньше минуты.
Для типизированных DNS-сбоев, тайм-аутов и обрывов соединения сохраняется
`retry_wait`: следующая попытка через 60, 120, 240 секунд и далее, максимум
через 30 минут. Число таких повторов не ограничено; параметры
`--retry-base` и `--retry-max` могут увеличить интервалы, но не сократить
начальную паузу ниже минуты. Уже скачанные файлы не скачиваются заново.

HTTP 403/429/5xx, ошибки сертификата, разбора, диска и кеша не повторяются
автоматически: задача получает `blocked`, следующие задания этого источника
ожидают проверки, остальные источники продолжают работу. Повтор `run` не
снимает `blocked` сам по себе. Исправление причины и разрешение конкретного
повтора требуют отдельного решения; обход ограничений доступа не выполняется.

`complete` означает завершение обхода конкретного задания по сохранённой
границе архива, а не наличие всех когда-либо опубликованных статей.
`complete_with_deferred` означает завершение с явно отложенными публикациями.
Коды завершения управляющей команды: `0` — все задания завершены без
отложенных позиций; `2` — есть отложенные позиции; `1` — остались блокировки
или незавершённые задания; `130` — остановка. Ни наличие PDF, ни завершение
очереди не заменяют проверку полноты, жанров, качества текста и оснований использования.

## Что сохраняется

- `data/raw/journals/<источник>/responses/` — точные HTML, PDF и HTTP-свидетельства.
- `manifests/imports/journals/<источник>/cache/` — связь адресов с файлами и SHA-256.
- `manifests/imports/journals/<источник>/articles/` — карточки с метаданными и
  ссылками на сохранённые ответы. Имена файлов основаны на SHA-256 URL карточки.
- `manifests/imports/journals/<источник>/metadata/` — отдельные записи режима
  `--metadata-only`; они не перезаписывают карточки уже скачанных PDF.
- `manifests/imports/journals/<источник>/deferred_issues/` — подтверждённые
  оглавления без ссылок на статьи или PDF, отложенные для дальнейшей работы.
- `manifests/imports/journals/<источник>/last_run.json` — итог последней команды,
  включая частичное завершение, число новых записей и причину остановки.
- `manifests/imports/journals/rate_limit/` — устойчивые паузы между запросами.

Для формы ЖЭТФ в `data/raw/journals/jetp/form_requests/` сохраняются точные
байты POST, а в `form_submissions/` — неизменяемые записи, связывающие запрос,
исходную HTML-форму и ответ сервера. Ответы находятся в обычном `responses/`.
Указатели `manifests/imports/journals/jetp/form_cache/` и `form_attempts/`
отделены от GET-кеша: ключ учитывает HTTP-метод, адрес, формат и тело запроса.
Разные тома и обычное открытие главной страницы не подменяют друг друга.

Все эти каталоги игнорируются Git. Кеш проверяется по адресу, размеру,
контрольным суммам тела и HTTP-свидетельства. Повреждение не исправляется
незаметным повторным скачиванием.

Статус `pdf_downloaded` означает получение открывающегося PDF с корректным
типом ответа и сигнатурой. Это не проверка качества текста или OCR.
`metadata_only` означает, что сохранены метаданные без скачанного PDF:
ссылка может отсутствовать, доступ может быть явно ограничен подпиской УФН
либо загрузка отключена флагом `--metadata-only`.
`skipped_non_russian` сохраняет метаданные нерусской или языково неоднозначной
карточки, но её PDF не скачивается. Аннотация не считается полным текстом.

Новые карточки имеют `registered=false` и
`training_eligibility=not_assessed`. Полные тексты не публикуются.

В старых выпусках «Квантовой электроники» отдельной карточки может не быть:
название, авторы и PDF-ссылка находятся в оглавлении. Тогда `document.url`
указывает на PDF, `metadata_page_url` — на выпуск, а `card_response` хранит
свидетельство HTML-оглавления. Выдуманная страница статьи не создаётся.

### Оглавления без ссылок

Если выпуск Quantum содержит узнаваемое оглавление с названиями, авторами
и номерами первых страниц, но без ссылок, сборщик сохраняет его отдельно
и продолжает обход остальных выпусков. В консоли явно выводится число
отложенных публикаций. Неизвестная или неоднозначная разметка по-прежнему
останавливает запуск: произвольная пустая страница не считается оглавлением.

Файл `deferred_issues/<хеш-адреса>.<хеш-снимка>.json` хранит позиции
оглавления и ссылку на точный исходный HTML с HTTP-свидетельством.
Версия зависит от контрольных сумм тела и HTTP-метаданных; новые снимки
не перезаписывают старые. Адреса статей и PDF не придумываются.
Эти позиции не входят в число собранных карточек и не регистрируются
в общих реестрах автоматически.

В `last_run.json` поля `deferred_issues_count`, `deferred_entries_count`
и `deferred_issues` описывают только оглавления, встреченные в данном запуске.
Завершение обхода с такими пропусками получает статус `complete_with_deferred`.
Достижение лимита карточек отмечается как `article_limit`; лимит запросов,
ошибка и прерывание сохраняют статусы `request_limit`, `error` и `interrupted`
даже при наличии отложенных выпусков. Сводка записывается при завершении
команды, поэтому во время работы файл может содержать итог предыдущего запуска.

15 октября на сохранённом выпуске `2026_56_5` проверено отложение 9 позиций:
без сетевых запросов, создания карточек или скачивания PDF. При продолжении
сетевого обхода этот выпуск больше не останавливает переход к следующим.
Для выпуска `2026_56_7` добавлена поддержка альтернативной фамилии в скобках:
«Ю. К. Кириченко (Бобрецова)» сохраняется целиком. Проверены все 10 позиций
выпуска, включая рубрику «Персоналия»; эта рубрика не превращается
в подтверждение научного жанра. В выпусках 5–7 отложено суммарно 27 позиций;
после них обход перешёл к архиву 2025 года.
Девять записей с метаданными из выпуска `2025_55_1` вошли в четвёртую
зарегистрированную партию, описанную ниже.

### Подтверждённый адрес выпуска Quantum

Адрес `/2025_55_2/` вернул HTTP 301 на `/2025_55_2-2/`; исходный ответ
сохранён без автоматического перехода. После отдельной проверки нового HTML
подтверждено: это выпуск 2025 года, том 55, номер 2. Суффикс `-2` — часть
адреса WordPress, а не диапазон номеров. Из оглавления получены 10 новых
записей только с метаданными; они вошли в пятую зарегистрированную партию.

Адаптер заменяет опубликованную ссылку только для этой точной пары адресов.
Другие суффиксы и неожиданные перенаправления не разрешены. Новый адрес
проходит обычные проверки `robots.txt`, кеша, минутной паузы и соответствия
заголовка выпуска. Оба исходных ответа — HTTP 301 и новый HTML — сохранены.
Обычный обход архива продолжается без дополнительных параметров.
Для прямого запуска через `--start-url` нужно использовать новый адрес:
старый адрес при таком запуске по-прежнему остановится на HTTP 301.

### Относительные ссылки в старых выпусках Quantum

В выпуске `2022_52_1` ссылки на карточки опубликованы без начального `/`:
например, `raboty-po-lazernoj-biofotonike/`. По правилам URL это адрес
`/2022_52_1/raboty-po-lazernoj-biofotonike/`, а не предполагаемая карточка
в корне сайта. 16 октября 2026 года этот вложенный адрес вернул HTTP 301
с `Location: https://quantum-electronics.ru/raboty-po-lazernoj-biofotonike/`;
корневая карточка затем получена с HTTP 200.

Сборщик сохраняет опубликованный вложенный адрес и исходный ответ 301.
Переход разрешается только при единственном `Location` на том же HTTPS-узле,
с тем же именем статьи в корне сайта. Другой адрес, HTTP 302 или цепочка
перенаправлений останавливают сбор. Перед новым запросом повторно действуют
проверки `robots.txt`, общего ограничения частоты и кеша.

Карточка сохраняется по фактическому адресу назначения; ответ 301 и его
`Location` остаются в исходных HTTP-свидетельствах. Повторный автономный
обход использует оба сохранённых ответа. Режим `--metadata-only` по-прежнему
не запрашивает PDF и не изменяет рабочие реестры.

### Рубрика внутри записи оглавления Quantum

В выпуске `2025_55_5` рубрика «Некролог» находится в одном абзаце с названием:
выделенная рубрика, перенос `<br>`, ссылка на публикацию и номер страницы
без авторов. Парсер поддерживает этот конкретный формат; произвольный текст
перед названием и неоднозначные ссылки по-прежнему отклоняются.

Из сохранённого HTML получены 14 новых карточек без сетевых запросов и PDF.

### Подготовка извлечения текста из зарегистрированных PDF

Список кандидатов от 17.10.2026 находится в
`manifests/imports/journal_extraction_20261017_v1/README.md`:
311 PDF без ранее извлечённого текста — 133 Иоффе, 83 ЖЭТФ и 95 «Писем».

исходных реестров. Из рассмотренных 917 PDF исключены 518 инвентарных
`recorded` и 88 уже обработанных файлов. Поздние загрузки в список не входят.

На момент подготовки это не был исполнительный пакет `rebuild_from_pdf.py`: у всех 311 кандидатов
сохранённые основания хранения относятся только к исходному PDF, не к новому
TXT. До отдельного оформления применимого основания обработки и хранения
производных извлечение не запускается. Рабочие реестры, права и допуск к
обучению при подготовке списка не изменены.

**Последующее согласование 17.10.2026:** пользователь принял DEC-024 —
закрытое извлечение и хранение TXT этой фиксированной партии по DEC-012 после

список кандидатов и его сводка не изменены. Ошибка регистратора, при которой
локальный TXT проверялся как новое получение по дате скачивания PDF, исправлена
после отдельного разрешения пользователя. Проектное решение не заменяет проверку условий,
не создаёт разрешений издателей и не расширяет права на другие файлы.

Согласованный список принимается только с параметром
`--derived-storage-approval`. Без него сохраняется прежний формат
`LocalFileRegistration`. Пробный запуск без записи реестров и файлов:

```bash
.venv/bin/python -B -u scripts/rebuild_from_pdf.py \
  manifests/imports/journal_extraction_20261017_v1/candidates.jsonl \
  --derived-storage-approval manifests/imports/journal_extraction_20261017_v1/approval.json \
  --extraction-version journal-pdf-text-v1 --limit 3 --no-ocr --dry-run
```

`--dry-run` всё равно читает PDF и извлекает текст; `--no-ocr` отключает
Tesseract. Сначала проверяется вся выбранная порция исходников, затем для
полученных TXT подготавливаются собственные точечные основания хранения.
`--export-pages` с этим согласованием запрещён: отдельные файлы страниц
не покрываются основанием одного полного TXT. `recorded`, права PDF,
жанры работ, метки и допуск к обучению не меняются.

## Проверка и регистрация сохранённых партий

Команда `scripts/register_journal_articles.py` работает только с локальными
файлами. Режим `check` повторно разбирает сохранённый HTML, сверяет метаданные
карточки, адреса, размеры, SHA-256 и HTTP-свидетельства, проверяет PDF.
Он не создаёт файлов, не меняет реестры и не обращается к сайтам.

```bash
.venv/bin/python scripts/register_journal_articles.py check ioffe
```

```bash
.venv/bin/python scripts/register_journal_articles.py check jetp
```

```bash
.venv/bin/python scripts/register_journal_articles.py check jetp_letters
```

```bash
.venv/bin/python scripts/register_journal_articles.py check quantum
```

Проверяется точный снимок, закреплённый в карточке, а не последняя версия из
кеша. Изменённая или повреждённая карточка останавливает проверку. Корректно
сохранённые нерусскоязычные карточки пропускаются с предупреждением.
Если одна работа есть в каталогах `articles` и `metadata`, совместимые записи
объединяются с сохранением PDF; конфликтующие версии требуют явного выбора.

Режим `register` переносит партию в `works`, `artifacts`, `retrieval_events`
и `work_aliases`. Он требует существующие основания для получения способом
`crawler` в масштабе `bulk` и хранения; их ID задаются повторяемым параметром
`--rights-record-id`. Сначала следует выполнить этот режим с `--dry-run`.
Полный список параметров:

```bash
.venv/bin/python scripts/register_journal_articles.py register --help
```

Весь выбранный пакет проверяется до атомарной записи. Повторная регистрация
того же пакета не создаёт дубликаты. Уже выданный `work_id` сохраняется при
согласовании с существующим реестром. Несовместимые записи внутри одной партии
не объединяются автоматически. `--max-articles` ограничивает выбранные работы
после проверки исходников и объединения двух каталогов, а не объём скачивания.

HTML-карточка имеет роль `metadata_only`, исходный PDF — `full_text` со
статусом извлечения `not_started`. Аннотация остаётся метаданными; фиктивный
TXT и OCR не создаются. Общее HTML-оглавление выпуска сохраняется в событии
получения источника, а не как отдельный артефакт каждой статьи. При неизвестной
полной дате сохраняется `published_year`, без выдуманного первого января.

Новые работы получают `eligibility_status=pending`. Импорт не создаёт
разрешения издателя и не меняет допуск к обучению. Обычный режим `register`
использует только уже записанные основания, не подтверждая условия DEC-012.
Исходные JSON-карточки сборщиков не перезаписываются: их поле `registered=false`
не является итоговым состоянием общих реестров. Результат регистрации нужно
проверять по реестрам, а не по этому полю.

```bash
  --accept-dec012 --dry-run
```

Без `--dry-run` выполняется атомарная запись. Основания `conditional`
с типом `lawful_access_research_assumption` относятся только к сбору и хранению
конкретных артефактов либо конкретного события получения общего оглавления.
Это внутреннее допущение проекта, не разрешение издателя. Оно не разрешает
будущие запросы ко всему источнику и не перекрывает применимые явные запреты.

Фактическое время скачивания остаётся в `retrieved_at`, а время внесения
сведений — в `created_at`. Поздняя регистрация не изображается как разрешение,
полученное до скачивания. Повтор сохраняет первую дату регистрации и не меняет
реестры; новые ограничения при этом проверяются на текущий момент.

остаются `pending`. Проверка общих реестров прошла без ошибок и предупреждений,
повторный импорт не добавил записей или файлов. Прежние записи сохранены.
В общих реестрах после этого импорта — **187 работ и 343 артефакта**.

проверяется вместе с реестрами. Исходные PDF и HTML также не попадают в Git.

## Ограничения обхода

Сборщик следует явным ссылкам на проверенных публичных путях; выбор тома
ЖЭТФ дополнительно использует проверенную опубликованную форму.
Идентификаторы статей не перебираются; закрытые разделы, платные английские
версии и авторизация не используются. Формы, не публикующие нужных ссылок,
могут ограничивать глубину доступного обхода: завершение команды само по себе
не доказывает полноту архива.

Перед сетевым запуском обновляется `robots.txt`. Ответ 404 или 410 сохраняется
как отсутствие файла правил, а не как разрешение издателя. HTTP 403, 429,
ошибки сервера и неожиданные перенаправления останавливают запуск; скрытых повторов,
переходов на другой узел и отключения проверки TLS нет. Неизвестные маски в
правилах или изменившаяся разметка требуют проверки.

При сетевой ошибке сохранённые исходники остаются на месте. После устранения
причины повторите ту же команду. Не запускайте цикл повторов при отказе доступа.

Если сервер однажды вернул HTML-ошибку с HTTP 200 вместо PDF, ответ остаётся в
кеше для воспроизводимости. После устранения причины его можно адресно
перепроверить: добавьте `--refresh-url` с точным адресом этого ответа и
`--allow-network`. Обновление выполняется один раз, когда обход доходит до
указанного URL; прежние байты не удаляются. Повреждённый по SHA-256 локальный
кеш этим флагом не обходится и требует отдельной проверки.

Старые страницы ЖЭТФ и «Писем в ЖЭТФ» используют KOI8-R; кодировка учитывается
при разборе, а исходные байты сохраняются без перекодирования.

У ЖЭТФ исторические тома на начальной странице выбираются через POST-форму;
для неё поддержан режим `--volume`. Обычный обход без этого параметра
15 октября завершился со статусом `complete`: получены 34 карточки
тома 170, выпуски 1–4; у 28 сохранён PDF, 6 пропущены как нерусскоязычные.
Это завершение доступного по ссылкам участка, не получение всего архива.

15 октября также завершён обход шести выпусков тома 169: обработаны все
53 карточки из сохранённых оглавлений, получены 45 русских PDF;
8 английских карточек пропущены без скачивания PDF. Начат обход тома 168
(2025), выбранного из опубликованной формы. Завершение скачивания не означает
регистрацию всех новых файлов: они входят в отдельные проверяемые партии.

Полнота всего исторического архива ещё не обеспечена: каждый выбранный том
обходится отдельно. Номера берутся из формы, а адрес — из ответа сайта;
перебор выдуманных адресов не используется.
У «Квантовой электроники» опубликованные адреса выпусков приводятся к
проверенному виду с завершающим `/`, чтобы не выполнять лишнее перенаправление.

декодирование остаётся строго прежним.

### Автоматическая регистрация новых загрузок

`scripts/register_continuously.py` работает отдельно от сетевых сборщиков.
Он сравнивает пути и SHA-256 сохранённых карточек, фиксирует только новые или
изменившиеся версии и проверяет их штатным инвентарным регистратором.
По умолчанию после каждого прохода выдерживается пауза 900 секунд.
Пустой проход не создаёт очередную партию и не меняет рабочие реестры.

Первый запуск можно начать с уже зарегистрированного полного снимка:

```bash
.venv/bin/python -B -u scripts/register_continuously.py run --seed-batch manifests/imports/journal_inventory_20261018_v1/batch.json --seed-receipt manifests/imports/journal_inventory_20261018_v1/receipts/ad6a41d93d074f12b81b76b4e399c623.json
```

Начальная партия и квитанция проверяются вместе; результат `--dry-run` не
подходит. Эти параметры нужны только при первом создании состояния. Для
продолжения после остановки:

```bash
.venv/bin/python -B -u scripts/register_continuously.py run
```

Добавьте `--once`, если нужен один проход без фонового ожидания. Команда сама
не переводит себя в фон; обычный запуск остаётся в текущем терминале.
Просмотр сохранённого состояния не запускает регистрацию:

```bash
.venv/bin/python -B scripts/register_continuously.py status
```

Состояние, журнал `events.jsonl`, неизменяемые партии и квитанции находятся
в `manifests/imports/continuous_inventory/` и не попадают в Git. Контрольная
точка обновляется только после записи реестров и квитанции. Прерванная партия
проверяется повторно без дублирования уже учтённых работ и файлов. Второй
автоматический регистратор в том же проекте не запускается, даже с другим
каталогом состояния. При Ctrl+C или SIGTERM текущая партия завершается перед
выходом; повреждённые свидетельства останавливают процесс для проверки.

Конфликты и нерусские карточки сохраняются в отчёте и считаются рассмотренными
для данной версии исходника, а не успешно зарегистрированными работами.
Неизменившиеся конфликты не повторяются бесконечно. После ручного разрешения
конфликта идентификаторов в реестре повторно запустите `register-inventory`
для соответствующего `batch.json`; изменение только реестра не запускает
пересмотр карточки.
Новые поступления во время текущего прохода остаются следующему проходу.

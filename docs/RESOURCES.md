## Зафиксированные роли моделей v1

- **B0 — `ai-forever/ruBert-base`:** обязательная общеязыковая базовая модель для оценки на прикладных задачах.
- **B1 — `ai-forever/ruSciBERT`:** основная научная базовая модель и исходная контрольная точка для продолженного предобучения MLM.
- **M1 (ruPhysBERT):** B1 после предобучения с адаптацией к предметной области на принятом физическом корпусе.
- **M2:** необязательная модификация M1 для работы с формулами; запускается только после прохождения критериев допуска по качеству обработки формул.

Другие модели ниже остаются кандидатами для дополнительного сравнения и не заменяют B0/B1 в минимальной матрице экспериментов.

## Модели (Hugging Face)

### ruSciBERT
- **URL:** https://huggingface.co/ai-forever/ruSciBERT
- **Роль:** B1 — основная научная базовая модель и исходная контрольная точка для продолженного предобучения
- **Авторы:** Sber AI + MLSA Lab (МГУ)
- **Архитектура:** RoBERTa, маскированная языковая модель (MLM)
- **Параметры:** ~123 млн
- **Словарь:** 50 265 токенов
- **Объём обучения:** ~6,5 ГБ научных текстов (рус.)
- **Лицензия контрольной точки:** Apache-2.0 по официальной карточке модели
- **Статья:** [Doklady Mathematics, 2022](https://www.mathnet.ru/danma345) — «ruSciBERT: языковая модель … для семантических векторных представлений научных текстов»

Карточка модели не раскрывает состав исходного корпуса обучения по источникам. Лицензия контрольной точки не заменяет отдельную проверку условий использования каждого PDF/HTML-источника физического корпуса.

### ruBERT-base
- **URL:** https://huggingface.co/ai-forever/ruBert-base
- **Роль:** B0 — обязательная общеязыковая базовая модель для оценки на прикладных задачах; результаты блокнота не считаются её количественной оценкой

## Наборы сравнительной оценки и смежные работы

### RuSciBench (2024/2025)
- **Статья:** https://link.springer.com/article/10.1134/S1064562424602191 (открытый доступ)
- **Суть:** первый набор сравнительной оценки для научных текстов на русском языке; данные из **eLibrary** (~182 тыс. статей после фильтрации).
- **Задачи:** 9 для русского + 9 для английского языка — классификация (OECD, ГРНТИ), регрессия (год, цитирования), информационный поиск.
- **Код:** https://github.com/mlsa-iai-msu-lab/ru_sci_bench_mteb
- **Данные:** https://huggingface.co/collections/mlsa-iai-msu-lab/ruscibench-66c4895619fb0935efdd95cb
- **Для НИР:** только внешний общенаучный набор сравнительной оценки с заранее зафиксированной версией — для проверки переноса и отсутствия деградации вне физической предметной области. RuSciBench **не является набором данных H2**, не задаёт `T_v1` и не используется как «физическое подмножество H2».

### RuSERRC (корпус статей об ИТ, методология)
- **Статья:** https://cyberleninka.ru/article/n/semanticheskiy-analiz-nauchnyh-tekstov-opyt-sozdaniya-korpusa-i-postroeniya-yazykovyh-modeley
- **Объём:** 1600 неразмеченных + 80 размеченных (NER + 6 типов отношений)
- **Вывод авторов:** для русского языка мало открытых корпусов для отдельных предметных областей; нужно дообучение BERT-подобных моделей.

### Распознавание сущностей в русскоязычных научных текстах
- **arXiv:** https://arxiv.org/abs/2011.09817

## Рубрикатор физики (ГРНТИ)

- **Раздел 29 — Физика:** https://grnti.ru/?p1=29
- Подразделы для классификации: 29.05 (частицы), 29.19 (твёрдое тело), 29.29 (атом), 29.31 (оптика), 29.35 (радиофизика) и др.

Для H2 создаётся отдельное версионированное отображение `T_v1` из 5–6 крупных классов ГРНТИ 29.xx и собственные разбиения по `work_id`, защищённые от утечек. Классификационные задачи RuSciBench остаются внешним общенаучным средством сравнительной оценки и не определяют H2.

## Качественные быстрые проверки в блокнотах (`draft/`)

Запуски в `draft/` — только **качественные быстрые проверки** интерфейсов моделей. Они не фиксируют версию данных, защищённые от утечек разбиения, начальные состояния генератора случайных чисел и доверительные интервалы, поэтому не являются воспроизводимыми результатами базового сравнения и не подтверждают H1/H2/H3.

1. В одном примере без обучения на образцах целевой задачи ruBERT дал близкие вероятности для классов «физика» и «биология»; это повод построить контролируемый эксперимент H2, а не вывод о качестве модели.
2. Отдельные примеры с задачей `fill-mask` для ruBERT возвращали бытовые слова; это демонстрация программного интерфейса (API), а не метрика адаптации к предметной области.
3. `text-generation` с BERT, содержащим только кодировщик и не имеющим декодировщика, даёт артефакты и не входит в задачи проекта.
4. Выбор ruSciBERT как B1 и исходной модели для M1 закреплён планом экспериментов в [PLAN.md](PLAN.md), а не результатами этих примеров.

## Прототип сбора (ещё не готовый корпус)

См. **[`docs/PARSERS.md`](PARSERS.md)** (подробно) и [`docs/ARCHITECTURE.md`](ARCHITECTURE.md) (схема).

Команды ниже демонстрируют текущее поведение прототипа, но не создают принятый
корпус и не обучают базовую модель. Каждый запуск должен получать новый версионированный выходной файл:
текущий интерфейс командной строки дописывает JSONL, а `--fresh` удаляет указанный файл. В целевом
конвейере содержимое `data/raw/` неизменяемо, а результаты последовательно и
с указанием версий строятся в `data/extracted/`, `data/processed/` и
`data/splits/`.

```bash
python3 scripts/scrape.py ufn \
  --max-docs 10 \
  --pdf-dir data/raw/pdf/ufn_smoke_20260818 \
  --pdf-text-dir data/extracted/ufn_smoke_20260818 \
  -o data/raw/ufn_smoke_20260818.jsonl

python3 scripts/rebuild_from_pdf.py \
  -i data/raw/ufn_100.jsonl \
  -o data/extracted/ufn_pdf_v1/records.jsonl \
  --text-dir data/extracted/ufn_pdf_v1/text \
  -n 10
```

Для получения готового корпуса пока отсутствуют:

- реестр данных со стабильными `artifact_id` и `work_id`, сведениями о происхождении, `access_basis`, раздельными разрешениями на хранение, оценку, обучение и распространение, хешами, версиями методов и статусами ошибок;
- автоматические модульные, интеграционные и регрессионные тесты на фиксированных контрольных примерах;
- воспроизводимый построитель производных слоёв и разбиений, защищённых от утечек;
- измеренные критерии допуска для OCR и извлечения текста из PDF по односторонним 95%-ным кластерным доверительным интервалам: верхние границы CER ≤ 3%, WER ≤ 10% и критических ошибок порядка чтения ≤ 5%; для H3 нижняя граница F1 обнаружения формул ≥ 0.90 и верхняя граница критической порчи формул ≤ 5%.

## Полезные команды

```bash
# Установка (из README)
python3 -m pip install -r requirements.txt

# Скачать модель локально
python3 -c "from transformers import AutoModel; AutoModel.from_pretrained('ai-forever/ruSciBERT')"
```

```python
# Качественная быстрая проверка API; не базовая модель и не проверка гипотез
from transformers import pipeline
m = pipeline("fill-mask", model="ai-forever/ruSciBERT")
print(m("Уравнение Шрёдингера описывает эволюцию [MASK]."))
```

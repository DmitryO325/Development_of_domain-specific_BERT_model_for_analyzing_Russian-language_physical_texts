# Сбор статей журналов Иоффе

`scripts/download_ioffe.py` получает публичные карточки и PDF по цепочке
«журнал → выпуск → статья → PDF». Сначала сохраняются исходники; OCR,
регистрация в рабочих реестрах и допуск к обучению выполняются отдельно.
Ограничения по годам нет. Разметка подразделов физики для скачивания не нужна.

## Источники

Поддержаны пять русских журналов [портала Иоффе](http://journals.ioffe.ru/):

- `1` — «Физика твердого тела»;
- `2` — «Физика и техника полупроводников»;
- `3` — «Журнал технической физики»;
- `4` — «Письма в Журнал технической физики»;
- `5` — «Оптика и спектроскопия».

Сборщик следует только опубликованным ссылкам. Он не перебирает идентификаторы,
не использует AJAX-разделы, авторизацию или обход ограничений.
Публичный доступ не записывается как полученное разрешение редакции:
рабочее основание исследования остаётся условным по
[DEC-012](DECISIONS.md), а сохранённые статьи имеют
`training_eligibility=not_assessed`.

## Первый запуск

Проверить только `robots.txt`:

```bash
.venv/bin/python -u scripts/download_ioffe.py probe --allow-network
```

Получить две статьи конкретного выпуска:

```bash
.venv/bin/python -u scripts/download_ioffe.py issue 2088 \
  --max-articles 2 --max-requests 6 --allow-network
```

По умолчанию используется HTTPS. При проверке 12 октября 2026 года в среде
сбора HTTPS не прошёл проверку цепочки сертификатов, а публичные страницы
по HTTP открывались. Для явно выбранного HTTP добавьте к команде:

```text
--origin http://journals.ioffe.ru
```

Отключения проверки TLS и автоматического перехода с HTTPS на HTTP нет.
Без `--allow-network` команда работает только с сохранёнными ответами.

## Сбор архива порциями

Для всего обнаруженного архива «Физики твердого тела», но не больше 60 сетевых
запросов за запуск:

```bash
.venv/bin/python -u scripts/download_ioffe.py journal 1 \
  --max-issues 0 --max-articles 0 --max-requests 60 --allow-network
```

`--max-issues 0` и `--max-articles 0` снимают ограничения на число выпусков и
статей. `--max-requests` ограничивает именно сетевые обращения, включая
проверку `robots.txt`, а не число статей. Пауза между завершением одного запроса
и началом следующего — не меньше 60 секунд; 60 запросов потребуют примерно
часа плюс время передачи файлов. Более строгая пауза сайта имеет приоритет.

Повторите ту же команду, чтобы продолжить после достижения лимита или
`Ctrl+C`. Кеш проверяется по URL, размеру и SHA-256. Сохранённые карточки и PDF
повторно не скачиваются; промежуточный обход начинается сначала, но читает
уже полученные страницы локально. Для другого журнала замените `1` его номером.
Используйте те же origin и каталоги, чтобы продолжение находило прежний кеш.

По умолчанию выбраны один выпуск, три статьи и 20 сетевых запросов.
`--max-articles` включает уже сохранённые статьи: для последовательного сбора
новых порций используйте `--max-articles 0` вместе с лимитом запросов.
Нулевой `--max-requests` разрешает непрерывный проход без лимита числа запросов.

## Где находятся результаты

- `data/raw/ioffe/responses/` — точные HTML, PDF, `robots.txt` и безопасные
  заголовки HTTP. Имена основаны на SHA-256, исходные байты не перезаписываются.
- `manifests/imports/ioffe/cache/` — проверяемые ссылки из URL в исходные ответы.
- `manifests/imports/ioffe/articles/` — отдельный JSON для каждой обработанной
  статьи: название, авторы, DOI, год, журнал, аннотация, ключевые слова и пути
  к исходникам. Аннотация не считается полным текстом статьи.
- `manifests/imports/ioffe/rate_limit/` — общая пауза для запусков через HTTP и
  HTTPS, в том числе при изменении каталогов партии в командной строке.

Эти каталоги игнорируются Git. Запись `pdf_downloaded` означает, что получен
HTTP 200, проверены MIME-тип и сигнатура, а PDF открылся без восстановления
или пароля и содержит страницы. Это не проверка качества OCR.
`metadata_only` означает отсутствие однозначной ссылки на PDF в карточке.

## Ошибки и ограничения

Для локальной проверки и переноса сохранённых партий в общие реестры добавлена
команда `scripts/register_journal_articles.py`. Начать можно без записи:

```bash
.venv/bin/python scripts/register_journal_articles.py check ioffe
```

Порядок регистрации, обязательные основания и ограничения описаны в разделе
[«Проверка и регистрация сохранённых партий»](JOURNAL_SCRAPING.md#проверка-и-регистрация-сохранённых-партий).
Ручной регистратор `register_local_pdfs.py` для этих партий не используется:
способ получения должен оставаться `crawler`, а не `manual_download`.

HTTP 403, 429, 5xx и перенаправления останавливают запуск без автоматического
повтора. Завершённый ответ сохраняется для проверки; `Retry-After` при 429/503
увеличивает паузу. Незавершённая передача не попадает в кеш. Повреждённый кеш
не игнорируется и не заменяется молча.

При каждом сетевом запуске заново проверяется `robots.txt`. Если появились
запрет нужного пути, неподдерживаемые маски правил или изменился формат
страницы, сбор останавливается. Для ранее сохранённых страниц действует
локальный снимок архива: автоматическое обновление оглавлений и карточек
новыми версиями пока не реализовано.

Модули: `src/collect/ioffe.py` — разбор HTML;
`ioffe_http.py` — одиночные запросы и паузы;
`ioffe_archive.py` — исходники и кеш;
`ioffe_collection.py` — обход и проверка PDF.

## Проверка 12 октября 2026 года

Контрольный запуск для выпуска `2088` сохранил две карточки и два PDF:
статьи `51651` и `51652`, соответственно 7 и 4 страницы, суммарно
1 972 188 байт PDF. Контрольные суммы сохранённых файлов совпадают с кешем.
Повтор той же команды без `--allow-network` завершился с нулём сетевых запросов.
Минимальный интервал между завершениями сохранённых ответов — 60,12 секунды.

85 новых тестов проверяют разбор, сохранность исходников, паузы, обработку
ошибок и продолжение. Весь набор проекта — 1290 тестов — прошёл; проверки
стиля и типов новых модулей также пройдены. Это проверка сборщика и двух
статей, а не утверждение о полном получении архива.

# Подготовка получения данных через API Math-Net.Ru

Состояние на 02.10.2026: Дмитрий Чебуков прислал описание API для получения
журналов, публикаций, метаданных и распознанных текстов. Описание сохранено,
с разрешения пользователя реализованы клиент одиночных запросов, локальный
архив и команда запуска. Они проверяются автономными тестами; реальные
HTTP-ответы Math-Net и совместимость форматов ещё не проверены. Скачивание
в этой работе не запускалось.

Основание и история переписки — в [журнале источников](SOURCE_AUDIT.md).

[`evidence/MATHNET_API_DESCRIPTION_RECORDED_2026-10-02.md`](evidence/MATHNET_API_DESCRIPTION_RECORDED_2026-10-02.md).

## Согласованный массив

Первоначальное предложение МИАН касается текстовых подложек и метаданных
восьми журналов для исследования модели на математических публикациях:

1. «Дискретная математика».
2. «Известия Российской академии наук. Серия математическая».
3. «Математические заметки».
4. «Математический сборник».
5. «Теоретическая и математическая физика».
6. «Теория вероятностей и ее применения».
7. «Успехи математических наук».
8. «Функциональный анализ и его приложения».

При проверке API нужно сопоставить эти названия с фактическими `jrnid`,
после чего явно выбрать журналы для первого прохода. Само присутствие
журнала в общем списке не означает включения в согласованную партию.
Примеры идентификаторов в письме не заменяют эту проверку.

Получаем тексты через предложенный API, а не автоматический обход страниц
и PDF сайта. Математические публикации учитываются отдельно: письмо не
меняет автоматически состав физического корпуса и протокол H1–H3.
Общего ограничения по годам и количеству статей не вводим; ограничение
первого проверочного запуска относится только к этому запуску.

## Адреса из письма

Базовый адрес в примерах: `https://www.mathnet.ru/api`.
Ниже приведено описание представителя, а не проверенная спецификация.

Конкретные примеры:

- `/api/journals/list` — список журналов с `jrnid`.
- `/api/journals/dan` — список публикаций журнала с `paperid`.
- `/api/journals/mm1234` — данные публикации; в письме указано `jrnid+paperid`.
- `/api/texts/mm1234` — распознанный текст публикации.
- `/api/authors/18133` — публикации автора.

В нумерованной части письма указана другая схема:

- `/journals` — список журналов.
- `/journals/<journal_id>/articles` — публикации журнала.
- `/journals/<journal_id>/articles/<article_id>` — данные публикации.
- `/texts/<article_id>` — распознанный текст.
- `/authors/<author_id>` — публикации автора.

Префикс `/api` в этой части не указан. Нельзя заранее считать схемы
равнозначными или автоматически перебирать все варианты адресов.
Для первого разрешённого запроса выбираем конкретный адрес из письма:
`https://www.mathnet.ru/api/journals/list`. Остальные маршруты определяем
по фактическим ответам, при необходимости уточняем у представителя.

## Метаданные и идентификаторы

В письме для карточки названы поля `title`, `annotation`, `keywords`, `udc`,
`year`, `author_name`, `author_id`, `journal_name`, `journal_id`.
Типы значений, вложенность, множественные авторы и представление пропусков
пока неизвестны. Сохраняем полный исходный ответ, включая дополнительные
поля, а не только этот перечень.

При проверке нужно установить:

- возвращается ли `paperid` числом, строкой или уже полным `mm1234`;
- как связаны `jrnid` из списка и `journal_id` карточки;
- есть ли разбиение выдачи на страницы и как определить её полноту;
- в каком формате и кодировке приходит текст, как обозначается его отсутствие;
- присутствуют ли язык, DOI, ссылки на статью, условия использования и
  дополнительные классификационные поля.

ГРНТИ в перечислении отсутствует. УДК не подменяет основной код ГРНТИ:
наличие названия и аннотации ещё не делает карточку готовым примером H2.
Совпадение автора или названия тоже не считается достаточным основанием
для объединения работ; сохраняем исходные идентификаторы и происхождение.

## Первый проверочный проход

После отдельного разрешения на сетевые запросы:

1. Выполнить один запрос списка журналов из сети с ранее отправленным IP.
   IP хранится только в `docs/evidence/`; доступ ещё не подтверждён.
2. Проверить HTTP-статус, тип содержимого и структуру. Сохранить точные байты
   и сведения об ответе; HTML-страницу ошибки не считать полученными данными.
3. Выбрать один журнал из согласованной восьмёрки и проверить получение
   списка его публикаций. Не запускать обход всех журналов автоматически.
4. Получить метаданные одной выбранной публикации и сверить идентификаторы.
5. Получить её распознанный текст, проверить связь с карточкой, язык,
   непустое содержимое и читаемость. Наличие текста не означает успешную
   проверку его качества для обучения.
6. Зафиксировать рабочие маршруты и форматы ответов. Только после этого
   переходить к пакетному получению выбранного массива.

Запрос публикаций автора не нужен для первого прохода: он способен привести
к работам вне выбранных журналов и создаёт лишние обращения.

## Ограничения клиента

Это настройки проекта, а не объявленные МИАН лимиты:

- один последовательный процесс; не менее 60 секунд между завершением
  запроса и началом следующего, с сохранением паузы между перезапусками;
- по умолчанию только проверка кеша, без сети; запрос требует флага
  `--allow-network`, принудительное обновление — также `--refresh`;
- понятный `User-Agent` проекта, тайм-аут и ограничение размера ответа;
- только HTTPS и проверенные маршруты `www.mathnet.ru/api`; перенаправления
  не обходят ограничение частоты и не ведут автоматически на другие сайты;
- повторный запуск использует проверенный локальный кеш и продолжает
  недостающие записи, а не скачивает заново всю партию;
- HTTP 401/403 останавливают получение для проверки доступа; не менять IP
  и заголовки с целью обхода ограничения;
- HTTP 429 и `Retry-After` требуют выдержать указанную сервером паузу,
  если она больше нашей; никаких циклов немедленных повторов;
- HTTP 404, пустое тело, неверный формат и отсутствие текста фиксируются
  раздельно; их нельзя выдавать за успешно полученную публикацию;
- автоматическое продолжение после неожиданного ответа запрещено до
  проверки причины. Список ошибок сохраняется, успешные ответы не теряются.

Тайм-аут по умолчанию — 30 секунд, предельный размер сетевого ответа —
32 МиБ. Все запуски используют один каталог состояния: смена `--state-dir`
создаёт независимый счётчик паузы и не должна применяться для ускорения
загрузки. Клиент проверяет адреса и не следует перенаправлениям.

Частота запросов в письме не указана. Если представитель сообщит иной
порядок работы, настройки нужно сверить с ним до продолжения.

## Локальное хранение

Используются отдельные каталоги, уже покрытые правилами `.gitignore`:

- `data/raw/mathnet_api/responses/` — неизменяемые тела ответов по SHA-256,
  с расширением `.bin`, независимо от исходного формата.
- `data/raw/mathnet_api/http/` — неизменяемые JSON-свидетельства HTTP-ответов.
- `manifests/imports/mathnet_api/` — индекс URL и ответов, состояние паузы;
  `attempts/` хранит исходы отдельных сетевых обращений, `unverified/` — ссылки
  на последние исходные ответы для повторного локального разбора.
  Выбор партии и связи карточек с текстами предстоит оформить при пакетном
  получении — текущая команда не строит их автоматически.
- `manifests/results/` — предусмотрен для будущих сводных отчётов; текущая
  команда пишет исход обращения в `attempts/`, а не создаёт отчёт по корпусу.
- `docs/evidence/` — переписка и сведения о доступе, включая IP.

Для каждого ответа сохраняются запрошенный и фактический URL, время UTC,
HTTP-статус, безопасные заголовки, размер и SHA-256 тела. Секреты, cookies
и заголовки авторизации в отчёты не попадают. Новая версия ответа не
перезаписывает прежнее тело. Нормализация текста выполняется отдельно.

Кеш получения не заменяет рабочие реестры корпуса. Регистрация работ и
артефактов будет отдельным шагом после проверки идентификаторов,
происхождения и условий использования. Само получение не устанавливает
`qa_status=passed` и не включает материалы в обучение.

## Реализованные модули

- `src/collect/mathnet_api.py` — одиночный HTTP-запрос, проверка адреса,
  сохраняемая пауза, блокировка, ограничения ответа и обработка ошибок.
- `src/collect/mathnet_archive.py` — неизменяемые тела и HTTP-свидетельства,
  проверка SHA-256 и размера кеша, журнал обращений, разбор JSON или текста.
- `scripts/download_mathnet.py` — команды `probe`, `journals`, `articles`,
  `article`, `text`; каждая получает не более одного ответа без обхода ссылок.
- `tests/test_mathnet_api.py`, `tests/test_mathnet_archive.py` и
  `tests/test_mathnet_download.py` — автономные проверки с поддельными
  транспортом и часами, без настоящих сетевых запросов и минутного ожидания.

Переиспользованы `HttpResponseSnapshot`, безопасные заголовки и `USER_AGENT`
из `src/collect/base.py`. Клиент ОИЯИ не изменён; маршруты, фильтры и
структура DSpace не перенесены в Math-Net.

JSON должен иметь MIME-тип `application/json` или `application/*+json` и
содержать объект либо список. Поля предметной схемы пока не интерпретируются;
ответы с полями `error`/`errors` требуют проверки и не принимаются в кеш.
Для текста пока поддерживается только `text/plain`: кодировка из `charset`,
UTF-8 при его отсутствии либо явно заданная `--encoding`. Форматы HTML, XML
или JSON-обёртка текста автоматически не преобразуются.

После транспортных проверок тело полного ответа HTTP 200 сохраняется до
разбора содержимого. Если формат оказался
неожиданным, тело и HTTP-свидетельство остаются для изучения, в `attempts/`
записывается `response_rejected`, но индекс успешного кеша не обновляется.
При отсутствии успешного кеша повторная команда разбирает сохранённый ответ
из `unverified/` без сети. Поэтому пропущенный сервером `charset` можно
исправить через `text ... --encoding cp1251`, если именно эта кодировка
подтверждена. Выбранная кодировка чтения запоминается в индексе, исходные
байты и HTTP-свидетельство не меняются.
Тела HTTP-ошибок транспорт не архивирует; их обращения имеют статус
`request_failed`, код HTTP и категорию ошибки без потенциально чувствительного
текста исключения. Ошибка обновления не скрывается возвратом старого ответа.
Повреждённый кеш требует отдельного разбора, а не молчаливого скачивания заново.

Синтетические тесты не подтверждают совместимость с живым API. Окончательный
разбор метаданных, пагинация и пакетное получение добавляются после
проверочного прохода. Автоматического сбора публикаций автора, скачивания PDF,
регистрации в корпусе или обучения в этой команде нет.

## Команды проверки

Справка и проверка уже существующего кеша не обращаются к сети:

```sh
.venv/bin/python scripts/download_mathnet.py --help
.venv/bin/python scripts/download_mathnet.py probe
```

Если кеш ещё пуст, `probe` завершится понятной ошибкой и кодом 1 — это
ожидаемо, автоматической попытки соединения не будет.

После разрешения на проверочный сетевой запрос:

```sh
.venv/bin/python -u scripts/download_mathnet.py probe --allow-network
```

Команда использует конкретный адрес `/api/journals/list`. Если ответ уже
сохранён и проверен, новый запрос не выполняется даже с `--allow-network`;
для явного обновления используется дополнительный `--refresh`.
Сообщение о чтении кеша не доказывает текущую доступность API.

Команды `articles`, `article` и `text` принимают точный идентификатор из
проверенного ответа; сейчас допустимы латинские буквы и цифры, длина 1–80.
Префикс журнала не добавляется автоматически. `--route-style examples`
использует схему из конкретных примеров письма; `--route-style nested`
явно выбирает альтернативную вложенную схему, для `article` нужен ещё
`--journal-id`. Перебора маршрутов нет. Идентификатор и схема должны быть
проверены до включения сети; выбранный журнал — из согласованного массива.

Проверки реализации без сети:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_mathnet*.py'
```

Проверка 02.10.2026: прошли 67 тестов Math-Net и все 598 тестов проекта;
Ruff, проверка типов и синтаксиса завершились без ошибок. Отдельный запуск
`probe` с пустым временным кешем корректно завершился без сетевого запроса.
Эти результаты относятся к реализации, а не к доступности живого API.

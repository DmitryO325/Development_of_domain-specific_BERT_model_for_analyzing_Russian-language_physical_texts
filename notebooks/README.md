# Первые эксперименты

Запускаем опыты на фиксированных локальных данных, не меняя рабочие реестры.
Это предварительные исследования, а не итоговая проверка H1–H3.

## Запуск

Из корня проекта установи зависимости:

```bash
.venv/bin/python -m pip install -r requirements-notebooks.txt
```

В VS Code открой ноутбук, выбери ядро `.venv/bin/python` и выполни ячейки
сверху вниз. Сначала:

1. [00_tokenization_pilot.ipynb](00_tokenization_pilot.ipynb) — сравнение
   токенизаторов ruBERT и ruSciBERT на одинаковых названиях и аннотациях:
   длины последовательностей, обрезание при 128/256/512 токенах и примеры
   физических терминов. Обучения и загрузки весов нет; сеть по умолчанию выключена.
2. [01_classification_baseline.ipynb](01_classification_baseline.ipynb) —
   TF-IDF + логистическая регрессия и простейший классификатор Dummy.
   Сравниваются название, аннотация и их объединение; метрики — macro-F1,
   показатели отдельных классов, матрицы и примеры ошибок.

## Данные и ограничения

Оба ноутбука привязаны к SHA-256 файла
`manifests/results/h2_candidates_jinr_clean_20261010_v2/cleaned_candidates.jsonl`.
Это локальная очередь кандидатов ОИЯИ, а не проверенная выборка только по физике.
Файл не входит в Git; на другой машине понадобится тот же снимок.
Токенизация исключает пустые и неоднозначные пары полей, а также их точные повторы,
но не подменяет тематическую и языковую проверку.

Для реальной классификации пока **нет проверенных меток**. Поэтому обычный запуск
второго ноутбука явно пропускает обучение на статьях и выполняет только отдельную
техническую проверку на искусственных строках. Её результат не является качеством
классификации корпуса.

Контракт файлов `labels.jsonl` и `review.json` описан внутри второго ноутбука.
Они должны появиться в `data/processed/experiments/classification_pilot/` после
согласования классов, разметки, проверки связанных версий и допуска именно к
этому опыту. Фиксированные обучающая и валидационная выборки общие для всех
представлений текста; словарь TF-IDF строится только на обучающей выборке.
Ручные метки здесь дают предварительный опыт, а не заменяют основной протокол
H2 с проверенными рубриками ГРНТИ.

## Сохранение результатов

Каждый реальный запуск сохраняет отдельную папку в
`artifacts/experiments/tokenization_pilot/` или
`artifacts/experiments/classification_baseline/`. Там находятся параметры,
версии, контрольные суммы входа и кода, выбранные идентификаторы и результаты.
Эти каталоги уже исключены из Git. Исходные тексты и рабочие реестры не меняются.

Перед коммитом ноутбуков очисти их выводы командой редактора «Очистить все выводы»
(Clear All Outputs): локальные тексты, таблицы и изображения не должны случайно
попасть в репозиторий. Старые ноутбуки в `draft/` не изменены.

Описание инструментов: [токенизаторы Transformers](https://huggingface.co/docs/transformers/main_classes/tokenizer),
[признаки текста scikit-learn](https://scikit-learn.org/stable/modules/feature_extraction.html#text-feature-extraction).
